# 《源界》已知踩坑与避雷记录

更新于 2026 年 11 月 21 日。收录本次项目对话、11 月 17 至 19 日的交接、相关提交、工作目录里的验收记录和现工程能够支持的结论。按玩家看到的现象查。文中的「旧版」指事件发生时的实现，「待复核」表示留下了反馈或日志，现有证据不足以确定当前故障或原因。审美依据与配图见[设计手册](源界美术与UI设计手册.md)。

## 1. 参考、反馈与改稿

| 出过什么问题 | 下次怎么做 |
| --- | --- |
| 想学战斗 UI，却拿主页当参考；搜过很多网页，玩家看到的变化仍很小。 | 截出商用游戏的实际选敌、受击、Buff 生效、终结技侧边提示和退场，各看事件前后两帧。若查材质教程，先把方法用在《源界》的一块真实按钮上，按游玩尺寸比对。 |
| 「平涂赛璐璐」被理解成只要有动漫人物；另一轮又把它压成了过分简约的几何按钮。 | 前者先核对轮廓、硬边明暗和文字层级；后者在同一个形里补支架、接缝、遮挡等有意义的细节。图标给足细节，整屏仍留呼吸空间。 |
| 用户分别喜欢 P1 的图标、末图的配色、另一个页面的材质，概念稿却被整张照搬。 | 交接逐项写明「这张取什么」。圈选也记清指向的是位置、删减、造型还是材料。「最下面两个可以用」只录入那两个。 |
| 「只移位置」带出了重画，「先停下来对齐」被当成继续迭代，「先用着」被记成定稿。 | 原组件移位时直接复用。需要对齐时先回答当下的问题。审美记录写到用户明确谈过的部位；战报黑、纸白、暖黄依然待改。 |
| 两张候选都换了些细节，缩进游戏仍长得一样；要求另起方案却沿用旧原画继续改。 | 在同一按钮中并排看大形，选不同的动作或构图出两稿。记录取舍，保留用户已接受的原件。 |
| 静态图做得好看，实际入口依然廉价；更换引擎又把尺寸、字重和图标问题带到了新引擎。 | 先用真实角色、中文名称、背景和游戏视窗确认问题。引擎迁移先复原认可过的站位和大小，再单独提出材质调整。 |

## 2. 大厅、角色页和美术资产

| 玩家感受到的雷点 | 复查与处理 |
| --- | --- |
| 首页被某位角色的专属场景占满；钴蓝、黑面和斜切铺得太多，变成枪战界面。 | 换两位发色、衣着不同的看板，检查脸和手势是否仍是第一视觉。大面归白与浅蓝，钴蓝有主次，红潮只占局部。 |
| 全域检索用罗盘像地图；公告、好友挤在一起；浮动图标太小，名字与按钮错位。 | 检索用接收天线；公告、好友各占一行，下方排名字；「行动计划」快捷名用「计划」。按图案实际重心对齐，点击名称和图形都应到同一入口。 |
| 白玉做成青灰、白图标浮在亮底上看不清、重复扫光让所有按钮都像在报警。 | 先关动画，在人物白衣和浅蓝背景上检查正面、底边、接触影，再按功能加动效。烤漆按钮看按压时的厚边变化。 |
| 红潮盖住浮标像贴纸，后来整个按钮明明在动，浪尖却没有升起来。 | 对齐上沿逐帧看浪尖的高度，同时观察浮标吃水、白沫和余波。截图裁切要包含越界部分，实际点击热区要让相邻入口可用。详情见[实机复盘](源界美术与UI设计手册.md)。 |
| 技能槽还用占位图，沈惠均的终结技附件也更正过；频谱当时由用户稍后补。 | 记录「角色、形态、用途、最新源图、运行时路径」。逐个点槽位看实图。主立绘、终结技、频谱、升格 CG 独立核对，待补的槽保留对应状态。 |
| 生图一次只取一枚太慢，把多角色塞在一张母图又损失清晰度。 | 一人一张三联母图，普攻、战技、终结技各自构图。现有交接示例是 3072 × 1024，裁后每格 1024 × 1024。需要四格的任务单独排版，检查裁边和黑白底上的透明边。[素材约定](cocos-hud-spec.md) |
| 收到角色包后漏看压缩包、闭眼图和原画；买好的资源出现在资产目录，招式里仍看不到。 | 清点用户指定路径及压缩包目录，区分源文件、运行时资产、代码引用和实机触发。用实际角色、技能或三只怪物展示；图集总览只用于挑素材。[素材交接](HANDOFF-battle-2026-11-18.md) |
| 角色待机拉长脖子、整人漂浮，眨眼时耳环一起跳；另一位角色几乎看不出动。 | 分别定格吸气、呼气和闭眼。对齐眼区，只给要动的部位分配网格权重。按角色独立调，不全局放大。历史方案是贴图眨眼和网格变形，对外交付时写实作名称。小惟拉颈与薇拉动效在旧交接列为暂缓，须看当前实机再判。[立绘实现](../charui/portrait-breath.js) |
| 升格大图没出现，或把展示了 CG 误解为解锁；长名牌挤住分栏。 | 若叶凛的升格插画曾专门修到大图槽，六阶效果文字与解锁状态分开保留。角色长名用实际姓名测试两行排版，再进入窄子页检查裁切。历史提交 `4aae4e3`。 |
| 同一行中文有几个字细得像换了字体。 | 旧模组文案新增的 57 个汉字没进字体子集，「署、晨、谢、忘、溢」等回退到系统字。按实际新增文案补字，检查打出的 WOFF2。有意用于模组名的宋体保留；标题源字体自身缺「凪」，补子集也补不出这个轮廓。历史提交 `f9bbdc6`。[字体脚本](../scripts/subset-ui-fonts.py) |
| 角色一处改对，技能标签、名册、筛选还显示旧元素；其他角色被顺手改了。 | 德可可改为「辐照」时同步了人物记录、技能标签、名册、规则筛选四处；棠梨仍是「演生」。同理，五星望月与 SP 长明用各自身份核对；星级上限六星，资料缺值与角色确认为几星分别记录。历史提交 `8fc61c8`。 |
| 世界观与实装口径被占位文案悄悄定死。 | 「同行者」覆盖全体可操作角色。元素沿用「汐流」「辐照」等定名，原画里的旧字另看。旧交接曾记录德可可模组页英文名和详情台词待核；引用到新物料前看当前页。角色身份、解锁条件、未定频谱和抽卡规则从对应资料读。 |

## 3. Unity 战场、输入与演出

人物立绘的单独专题收录了小惟断肩的修前、修后图层，沈惠均的披风遮挡、ELIOT 的双臂拆分、新角色导入流程与验收方法。[人物战斗立绘制作与修复](人物战斗立绘制作与修复.md)

| 出现过的现象或验收风险 | 怎样定位 |
| --- | --- |
| 网页 HUD 与 Unity HUD 相叠，单看加载完成的截图却很正常。 | 从刷新录到可操作。区分原生 HUD 可收数据的 `commandHudReady` 和真正画出首帧的 `commandHudPainted`。在接管点同时检查首领、行动条、技能栏和左下四人。[原生 HUD 桥](../battle3d/native-hud.js) |
| 截图只剩人物和冰面；另一次修了头像就误以为整个 HUD 已修。 | 截父页面全景，检查双方状态、当前行动者、选技区、选中目标和侧边提示。进战、选敌、开大、手动重获控制各留一帧。[旧版截图经验](HANDOFF-ui-2026-11-19.md) |
| 目标框或飘字在设计稿正确，镜头一推近却偏离目标；靠边状态面板不易读。 | 分辨 Unity 画布坐标、iframe 与网页舞台缩放。沿已有 `screenPos`／`posOf` 投影接口，用近景远景、两侧目标和切换目标逐一检查。 |
| 点过战场后快捷键失灵，或空格确认一次行动执行两次。 | 先点网页按钮再按键，再点 Unity 画布按同样的键。记录焦点、当前角色和行动次数。旧 Cocos iframe 还曾吞冒泡事件，那个版本从捕获阶段转发。 |
| 左下属性标在亮冰面上消失；血条看成一根红线；多段命中后找不到当前目标。 | 同帧看浅色冰面、深蓝幻海以及目标切换。槽有底、描边、填充、扣血残影；粗字的字心清楚。段数多时保留每次命中，错开数字；行动提示退场后应看得见下一步。 |
| 旧构建没退出就截图，误以为改动没生效；重生成旧模板又冲掉后来编辑的页面。 | 查本轮构建日志结尾、访问的入口、浏览器拿到的版本。改模板生成的节点就核对生成来源。共享的 `play.js`、`play.css` 编辑前看差异，避免另一个窗口的演出修改被整页替换。[交接记录](HANDOFF-ui-2026-11-19.md) |
| 电脑上有插件或特效包，买家预览很好看，到实际的一招里却认不出。 | 核对导入的预制体、着色材质、招式映射、触发事件和实际命中点。幻海要看展开、持续、结束；衍生飘字还要用满足条件的角色养成触发。 |
| 2.5 GB 怪物包只接三个，压缩包大小引发卡顿担心。 | 三只成品核对模型、材质、贴图与动画依赖，再分别量首载和三只同屏战斗的帧耗。包体大小本身不能给出手机帧率。历史战场还用过基础几何占位，接模型后需要从默认入口看三只的身份、站位、选敌和死亡。[遭遇配置](../data/battle/encounter-beasts.json) |
| 演示能播大招，被误认为已能打一场；训练里大招立刻可用，又误报成正式规则。 | 从普通入口走「选择 → 扣费 → 行动 → 命中／治疗 → 下一位 → 胜负 → 重开」。另记训练队、幻海演示、精英战和正式入口的预充能、阵容、敌方数值。 |
| 冰霜的重演出随 ELIOT 多段攻击反复出现。 | 调试时同时计数主体冰霜、投射物、伤害事件、命中反应和飘字。当前表现层对 ELIOT 的主体命中用行动内共享标记，对并行冰晶及回响另限冰弹。逐段伤害、受击和数字仍各走对应事件。[演出实现](../battle3d/play.js) |
| 大招手机看着清楚，桌面放大后发糊；自动化环境还出现过 H.264 播不了。 | 前者对照同一时间点、实际加载的文件、视频分辨率和显示矩形。ELIOT 当前在宽度达到 1100 CSS 像素时选桌面视频，高清原画可覆盖的段落与从预览片放大的段落分开看。后者在历史本机用带 H.264 支持的 Edge 验过。两种现象分别留证。[播放入口](../battle3d/play.js) |
| 用户端偶发画面拉伸，刷新或重置缩放后恢复。 | 历史现象，原因待复核。复发时记录窗口、浏览器缩放、画布实际宽高和设备像素比；在同一视窗重开比较，避免把主动降低原画分辨率当作默认修法。 |

## 4. 战斗机制、统计与养成

这里同时记下了设计要求中特别点名的回归风险。其验证依据是仓库测试，不能据此倒推每一种情况都曾在线上出错。[望月 V1.1 回归用例](../tests/battle/rin-v11.test.js)

| 容易混淆的两件事 | 项目里的判定例子 |
| --- | --- |
| 一次行动与一次命中 | 沈惠均六段命中可以逐段享受花期。花期按受益者行动结算，两次队友主动行动的花信门槛也不会因为六段就推进六次。 |
| 满血、实际治疗和溢出治疗 | 满血目标的实际恢复量为零，望月仍按溢出量的 30% 积花息；同时有伤员和满血者时逐目标记。ELIOT 主动耗血不能记成治疗。 |
| 施加时血线与命中时血线 | 花期额外增伤要求当前生命严格高于 80%。刚好 80%、从上方跌破、被治疗后重新超过都要能区分，重新施放刷新持续时间。 |
| 强化花信、自动花信、旧救援花苞 | 终结技强化追击独立，自动追击消耗一份阈值、余额保留；六阶救援走原有花苞。保持原有 110 超限值与角色形态边界。 |
| 队友主动出手、被动追击与幻海复现 | 花信不给 ELIOT 主动攻击采样；符合规则的直接伤害可记入梦痕和幻海，复现结果不会再次入账。用追击和复现同时发生的一手核对。 |
| 技能机制通过与平衡目标达成 | 望月旧版实测记录中，冰火队训练、精英各模拟 12 场，个人输出均值分别为 0.71%、0.82%。设计目标为约 15%–20%。条件受队伍、敌人、时长、养成和自动策略影响；个人列也看不到为队友提供的增伤。后续平衡需另测。 |
| 一个演示数字与当局数据 | 战报预览有固定的 15,000,000 样例。实战结算沿事件区分伤害、有效治疗和承伤。四人全零时、同指标接近时、切换页签后，检查总数、排名、人物、分隔符是否一致。重开后读新对局，失利状态另查奖励。[结算实现](../battle3d/operation-report.js) |
| 旧队伍、旧血量与当前试用队 | 100 万和德可可是旧要求。冰火试用队为沈惠均、若叶凛·望月、ELIOT、思惟诺姆；三敌各 500 万。普通编队、训练、精英各读其入口，避免试用配置影响所有对局。 |
| 文案、养成存档和角色技能实际口径 | 满级技能、新增等级、旧存档已投资源、商店或消耗品旧名称各自核对。望月普攻上限从 6 扩到 10，旧救援资源改称「急救花苞」。升格 CG 的显示、六阶文字和玩家真实解锁独立验证。[望月配置](../data/skills/rin.json) |

## 5. 本地服务、发布与历史引擎

- **同一台电脑两个浏览器都打不开本地链接。** 当时后来恢复，故障当刻的监听与响应记录缺失，根因待复核。复发先在本机用 `Test-NetConnection 127.0.0.1 -Port 8765` 查监听，再用 `curl.exe --noproxy "*" -I http://127.0.0.1:8765/battle3d/report.html` 查具体页面。端口不通查服务，HTTP 404 查根目录，200 但白屏就查脚本请求、控制台与 MIME。只有直连正常、浏览器仍失败时，再比较代理设置。旧 Windows 环境确实发生过模块脚本被送错 MIME。[本机服务说明](HANDOFF-ui-2026-11-19.md)
- **本机能看、项目页打开却丢图。** 本机根地址和 Pages 的项目子路径不同。入口、资源、跳转链接用项目相对路径，核对发布分支和 Pages 部署记录。只有本地截图时写「本地预览」。历史 PR 的状态和旧工作目录的内容都应按当前仓库确认。[发布流程](../.github/workflows/pages.yml)
- **构建日志里出现 error，或网页控制台有一条 404。** 看最末退出状态、失败请求的具体 URL 和当次可见后果。旧怪物构建日志同时有警告与成功退出；旧浏览器日志还有 404、WebGL `INVALID_ENUM` 和 `MeshCollider` 缺失提示。当时的摘录没有给出足以归因的完整上下文，保留为待复核记录。
- **旧 Cocos 3.8.8 的泛光开关会让 RenderRoot2D 小人和特效消失。** 切换前后先看同机同帧的可见性。另一轮整场发灰来自雾距 11–22 米罩住了整个战场。两条都属于当时的渲染配置；Unity 的材质与泛光要按当前管线单测。[历史引擎记录](HANDOFF-battle-2026-11-18.md)
- **旧场景一启动就在放大招，或保持上次演出镜头。** 再执行演出生成脚本曾写回 `playOnStart`，保存场景时镜头也可能停在演出帧。普通进场查常态镜头和角色可见性，另从演示入口查主动开演条件。[场景记录](HANDOFF-battle-2026-11-18.md)
- **旧 Cocos 构建与编辑器行为不同。** 历史工程的 loose 转译会把 `[...map]` 变成 `[map]`，当时改用 `Array.from(map.entries())`。编辑器占用项目会锁构建；该版本工具曾以退出码 36 表示成功，还要同步产物和运行全屏补丁。复现旧问题时对照对应版本和命令，当前 Unity 构建另看其日志。[旧工程交接](HANDOFF-cocos-battle-2026-11-17.md)
- **旧 Spine 特效包进不来，或一组序列帧就拖慢首载。** 二进制包出现过 3.8.75，另一批是 2.1，各用匹配的运行库烘焙。旧版序列帧一度约 23 MB，总构建约 34 MB；后续记录里有精选 15 套打包约 2.3 MB 的结果，两组的内容规模不同。对当前 WebGL 项目分别记录首载、包内实际依赖、运行帧耗。[旧素材记录](HANDOFF-battle-2026-11-18.md)
- **旧交接会同时留下后续已改的结论。** 11 月 17 日的怪物呈现、生图范围、锁定功能，与后来的购入建模、技能三联图及已接通的回合系统有明确时间差。接手时按对象查最后一次更正，再查对应入口。项目里两个窗口的修改都应从当前工作树开始，旧快照只供对照。
